# chem-agent — химический модуль НИОКР

Прототип мультиагентной системы для химпрома: по набору соединений
пользователя генерирует реакции, валидирует их, оценивает экономику и
ранжирует. Здесь живёт химический модуль — шаблонная генерация реакций
из корпуса (RDKit + RDChiral + RXNMapper).

Сейчас идёт этап 2 (до 01.12.2026). Критерии: 2.1 — ≥10 валидных реакций из
подмножества; 2.2 — векторная БД; 2.3 — экономика с точностью ≥85%.
Полное ТЗ — `docs/tz.md`, очередь задач — `docs/roadmap.md`.

## Команды

- `make test` — быстрые тесты (~3 с). Запускай после каждого изменения кода.
- `python -m pytest tests/test_template_engine.py::<имя_теста>` — один тест
- `make lint`, `make format` — ruff; хук сам форматирует .py после правки
- `make demo` — полный прогон на демо-корпусе → `outputs/demo/`
- `make fixtures` — пересобрать размеченные фикстуры (нужен rxnmapper)
- `python -m chem_agent.template_engine {map,extract,apply} --help`

## Где что

- `src/chem_agent/template_engine.py` — весь движок: map → extract → apply
- `data/raw/` — реальный корпус; не в git, только чтение
- `data/manual/inorganic.csv` — курируемые реакции; поле `source` обязательно
- `tests/fixtures/` — размеченные копии демо-данных; руками не править, только `make fixtures`
- `docs/decisions/` — принятые решения; каждое ссылается на тест, который его охраняет

## Химические правила (их нарушение — тихая ошибка в результатах)

- IMPORTANT: элементарная сера — `S1SSSSSSS1`. SMILES `S` — это H₂S.
- NaOH — `[Na+].[OH-]`. Электроэнергия — `resource`: не молекула, в шаблонах не участвует.
- Round-trip обязателен; `--no-roundtrip` — только для сравнения.
- Разнообразие считаем по `type_key`, а не по уникальным reaction SMILES.
- Реакция без `precedent_id` пользователю не выдаётся.
- Подробности и термины — скилл `chem-conventions`.

## Метрики

- Любую метрику показываем рядом с бейзлайном (константный или частотный предиктор) и командой воспроизведения.
- Цифры из `data/demo/` синтетические: не выдавай их за покрытие реального корпуса.
- Критерий 2.1 считаем на весь набор, а не на каждое вещество (`docs/decisions/0004`).

## Как работаем

- Правки в нескольких файлах или в химической логике — сначала план.
- Нашёл химический дефект — сначала регрессионный тест, потом исправление.
- Упавший химический тест — это регрессия. Не правь ожидания, пока не понял причину.
- Архитектурное решение — новый файл в `docs/decisions/` по образцу существующих.
- Проверка осмысленности реакций — субагент `chemistry-reviewer`; заявленные числа — `metrics-auditor`.
- Результаты прогонов — в `outputs/<дата>-<метка>/`, выводы — в `docs/findings.md`, статус задач — в `docs/roadmap.md`.
- При сжатии контекста сохраняй: изменённые файлы, команды тестов, открытые химические вопросы.
