# Дорожная карта

Задачи идут по приоритету. У каждой есть критерий «готово, когда» — это
проверка, которую Claude запускает сам. Статус обновляется в этом файле.

Этап 2 заканчивается 01.12.2026. P0 — то, без чего не сдать этап 2.

## P0

### R1. Прогон на реальном корпусе
`/coverage-run data/raw/<файл> full-v1`
**Готово, когда:** в `docs/findings.md` есть таблица покрытия по 6 веществам
(открытый режим и `--internal-only --depth 3`), а chemistry-reviewer
проверил 30 случайных кандидатов.
Статус: корпус подготовлен (`make corpus`, решение 0008); прогон покрытия не начат.

### R2. Сравнение с LLM-пайплайном на одной метрике
Пересчитать 224 уникальные реакции LLM по `type_key` (функция уже есть) и
сравнить с шаблонами по тем же 12 видам сырья. Разложить 58% брака LLM по
причинам (R1–R5 или chem_rules; чинится ли балансировщиком).
**Готово, когда:** таблица «метод × вещество × реакции × типы» в
`docs/findings.md`, проверенная metrics-auditor.
Статус: не начато. Нужны выгрузки LLM-пайплайна.

### R3. Ручная библиотека ≥ 20 реакций
Серная цепочка, щелочные процессы, промышленное этоксилирование и
пропоксилирование, если их нет в корпусе. Электрохимия (хлор-щелочной
электролиз) — отдельный вопрос: шаблоны не описывают электроэнергию, нужен
флаг ресурса.
`/add-manual-reaction ...`
**Готово, когда:** ≥ 20 строк с источниками и все тесты зелёные.
Статус: 7 из 20.

### R4. Балансировщик
Полное уравнение с коэффициентами: побочные продукты (H₂O, соли,
противоионы) через ядро матрицы атомов (sympy nullspace) с пулом типовых
побочных продуктов. Нужен экономике (расход сырья на тонну продукта).
**Готово, когда:** у каждого кандидата из демо либо сбалансированное
уравнение, либо явная причина отказа; тесты на нейтрализацию, этоксилирование
и сульфатирование.
Статус: не начато.

### R5. Векторная БД (ТЗ 2.2)
Difference fingerprints реакций (RDKit), хранилище (FAISS или Chroma),
дедупликация и поиск похожих.
**Готово, когда:** ≥ 10 реакций с попарно различными векторами, запрос
«похожие на X» возвращает реакции того же `type_key`, есть тест.
Статус: не начато.

### R6. Методика точности экономики (ТЗ 2.3)
Сначала договориться с заказчиком (см. questions-for-customer.md): эталонный
набор из 5–10 реакций с «правильными» цифрами и метрика (MAPE?). Затем
расчёт по стехиометрии из R4 и ценам.
**Готово, когда:** скрипт оценки на эталонном наборе печатает метрику, и
metrics-auditor подтвердил методику.
Статус: блокировано ответом заказчика.

## P1

- **R7. Отсечение сети по оценке:** `--beam N` на стадию с внешней функцией
  оценки (экономика, близость к целевым классам продуктов).
- **R8. Гибрид с LLM:** LLM работает только за пределами покрытых `type_key`;
  список исключений передаётся в промпт.
- **R9. Офлайн/онлайн:** предрасчёт химии в БД; онлайн — только экономика по
  текущим ценам. Замер времени ответа — это цифра для слайда «1000 часов → X».
- **R10. Условия:** QUARC, включая стадии количеств реагентов и агентов;
  агенты уже лежат в колонке `agents` после map.
- **R11. Уровни доверия (решение 0007):** поле `evidence_level` в
  candidates.csv; I — кандидат совпадает с реакцией корпуса по канонической
  записи, II — аналог по шаблону. **Готово, когда:** тест на I/II зелёный,
  в отчёте о покрытии числа по уровням.
