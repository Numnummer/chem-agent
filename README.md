# chem-agent

Химический модуль НИОКР «Мультиагентная система генерации идей и анализа
для химической промышленности». Шаблонный генератор реакций: извлекает
превращения из корпуса и применяет их к веществам пользователя с
проверками, прецедентами и многостадийными маршрутами.

## Первый запуск

```bash
cd chem-agent
git init && git add -A && git commit -m "Начальная структура проекта"
python -m venv .venv && source .venv/bin/activate    # Windows: .venv\Scripts\activate
make setup        # или: pip install -e ".[mapping,dev]"
make test         # 13 тестов, ~3 с
make demo         # полный прогон на демо -> outputs/demo/
```

Положите реальный корпус в `data/raw/` (формат — `data/README.md`) и
запустите Claude Code в папке проекта:

```bash
claude
```

## Что настроено для Claude Code

| Файл | Зачем |
|---|---|
| `CLAUDE.md` | контекст проекта, команды и химические правила; читается в каждой сессии |
| `.claude/settings.json` | разрешения без запросов (тесты, линтер, движок, git только на чтение); запрет правок `data/raw/` и `tests/fixtures/` |
| `.claude/hooks/ruff-after-edit.sh` | после каждой правки .py-файла — ruff format и check; оставшиеся ошибки уходят Claude |
| `.claude/skills/coverage-run/` | `/coverage-run <корпус> <метка>` — прогон покрытия со сравнением и отчётом |
| `.claude/skills/add-manual-reaction/` | `/add-manual-reaction <реакция>` — добавить курируемую реакцию с проверками |
| `.claude/skills/chem-conventions/` | соглашения по SMILES, термины, метрики; Claude подгружает сам |
| `.claude/agents/chemistry-reviewer.md` | независимая проверка химической осмысленности результатов |
| `.claude/agents/metrics-auditor.md` | скептическая проверка заявленных метрик (бейзлайны, утечки, определения) |
| `tests/` | регрессионные тесты на все найденные дефекты — главный способ для Claude проверять свою работу |
| `docs/` | ТЗ, архитектура, решения, выводы, дорожная карта, вопросы заказчику |

## С чего начать в Claude Code

Задачи лежат в `docs/roadmap.md` по приоритету. Удобные первые запросы:

```
/coverage-run data/raw/reactions.csv full-v1
```

```
Прочитай docs/roadmap.md, задача R4 (балансировщик). Составь план
в plan mode: какие функции, какой пул побочных продуктов, какие тесты.
Реализацию начнём после согласования плана.
```

```
Вот выгрузка реакций LLM-пайплайна: @data/raw/llm_output.csv. Посчитай
разнообразие по type_key и сравни с шаблонами (задача R2). Цифры
проверь через субагента metrics-auditor.
```

## Практики, которые здесь работают

- **Одна задача — одна сессия.** Между несвязанными задачами — `/clear`.
  Сессии удобно называть через `/rename` (например, `r4-balancer`) и
  продолжать через `claude --resume`.
- **Сначала план.** Для задач из roadmap включайте plan mode (Shift+Tab),
  правьте план и только потом давайте реализовывать.
- **Проверка — тестами.** У каждой задачи в roadmap есть критерий «готово,
  когда». Просите Claude показать вывод тестов, а не сообщить, что всё работает.
- **Второе мнение.** Перед показом результатов заказчику: «проверь выборку
  через chemistry-reviewer» и «проверь эти цифры через metrics-auditor».
- **Если Claude дважды ошибся в одном и том же** — `/clear` и новый запрос,
  в котором учтено, что пошло не так.
- **CLAUDE.md держите коротким.** Правило, которое Claude соблюдает и так,
  удаляйте; правило, которое нарушает, превращайте в тест или хук.
